# 대시보드 Implementation Plan

> 상태: IMPLEMENTED - 2026-09-30 실제 API 전용 전환. 아래 Phase 0~5는 초기 구현의 역사적 기록이다.

## Phase 7: 디자인 시스템 및 화면 리뉴얼

- `docs/DESIGN_SYSTEM.md`에 컬러·타이포그래피·간격·컴포넌트·차트·반응형 규칙을 확정한다.
- 사용자 노출 명칭을 `대시보드`로 통일하고 `YS` 표식을 제거한다.
- 공식 Streamlit 테마, 공통 CSS, Plotly 스타일과 다섯 화면의 정보 계층을 적용한다.
- 기사 목록은 처음 일부만 보여주고 나머지는 펼쳐 볼 수 있게 한다. 기존 데이터·API 로직은 변경하지 않는다.
- 자동 테스트 및 실제 로컬 화면을 브라우저에서 확인한다.
- 결과: 테스트 26개 통과, 새 서버에서 아침·장 마감·실시간·설정 화면 및 390px 모바일 폭(가로 넘침 없음)을 확인했다. 실제 API로 생성한 로컬 리포트 화면을 README에 첨부했다.

## Phase 6: 실제 API 전용 전환 및 차트 오류 복구

- 2026-09-30 사용자 요청으로 런타임 샘플 뉴스·시장·실시간 공급자를 제거한다.
- 빈 인증정보는 `missing`, 일부 입력은 `invalid`로 구분하고 기능을 비활성화한다.
- 새 DB에는 예시 관심 목록을 자동 등록하지 않는다. 기존 관심 목록은 유지한다.
- 과거 가상 리포트는 일반 조회에서 숨기되 SQLite 원본은 삭제하지 않는다.
- 아침 종목·테마 차트와 저녁 시장·투자자 차트에 고유 키를 부여한다.
- 자동 테스트는 네트워크 없는 테스트 대체 공급자로 계속 실행한다.

2026-09-30 NAVER API HUB 이관 후 자동 테스트 22개 통과. Ruff 검사 및 포맷 검사 통과. 외부 의존성 `exchange-calendars`에서 NumPy 시간 단위 deprecation 경고가 발생하지만 달력 테스트는 통과한다.

실제 키로 NAVER API HUB 뉴스 검색 단독 조회, 키움 모의 REST 시세·순위 조회, 키움 모의 WebSocket 구독 ACK를 확인했다. 뉴스 조회는 키워드·시간 범위에 따라 1,000건 검색 상한 경고가 발생할 수 있다. 전체 UI 생성 흐름과 WebSocket 실제 체결 수신은 별도 검증 대상이다. 이전 오프라인 샘플 모드는 Phase 6에서 제거했다. 비밀정보와 SQLite 파일은 Git 추적에서 제외한다.

## 운영 방식

- 코드 작업은 Phase 단위로 진행한다.
- 각 Phase 시작 전 해당 스펙과 완료 조건을 확인한다.
- 각 Phase 종료 시 테스트 결과와 변경 요약을 기록한다.
- 완료 조건을 만족하지 못하면 다음 Phase로 넘어가지 않는다.
- 새로운 요구는 즉시 코드에 넣지 않고 PRD 또는 ADR을 먼저 갱신한다.

## Phase 0. 설계 승인

### 작업

- PRD 검토
- 컴포넌트 스펙 검토
- 아키텍처와 ADR 검토
- 미결정 입력 확정

### 승인 필요 사항

- PRD·컴포넌트 스펙·아키텍처·ADR 전체의 최종 구현 승인

### 완료 조건

- 모든 ADR이 `사용자 승인` 상태다.
- 필수 기능과 제외 기능이 사용자 의도와 일치한다.

## Phase 1. 프로젝트 기반과 도메인

### 작업

- Python 프로젝트 설정
- 환경변수와 `.gitignore`
- 도메인 모델과 공통 오류
- SQLite 초기화
- 관심 종목·테마 저장소
- 샘플 공급자
- 빈 샘플 DB의 1회 초기 데이터 등록

### 테스트

- 관심 종목 CRUD
- 중복 종목 방지
- 테마·키워드 저장
- 리포트 스냅샷 저장·조회
- 샘플 공급자 전체 흐름
- 샘플 초기 데이터의 1회 등록 및 사용자 삭제 유지

### 완료 조건

- API 키 없이 테스트가 통과한다.
- 비밀정보가 저장소에 포함되지 않는다.

### 작업

- 수급·순위 응답 정규화
- 업종 매핑
- EveningFlowService

- 리포트 저장

### 테스트

- `docs/specs/EVENING_FLOW_REPORT.md`의 테스트 항목 전체

### 완료 조건

- 샘플 데이터로 저녁 사용자 여정이 동작한다.
- 실제 키가 있으면 조회 API를 수동 검증한다.
- 주문 엔드포인트 호출이 존재하지 않는다.

## Phase 4. 장중 관심종목 실시간 체결

### 작업

- RealtimeMarketProvider 계약
- 키움 `0B 주식체결` WebSocket 공급자
- SampleRealtimeProvider
- 최근 5분·최대 300건 메모리 버퍼
- 실시간 종목 카드와 체결가 선 그래프
- 연결 시작·중지·오류 상태 UI

### 테스트

- `docs/specs/LIVE_WATCHLIST.md`의 테스트 항목 전체

### 완료 조건

- 실제 키 없이 샘플 스트림을 시작·중지할 수 있다.
- 실시간 이벤트가 SQLite 또는 리포트에 저장되지 않는다.
- 실제 키가 있으면 모의투자 WebSocket을 수동 검증한다.

## Phase 5. 통합과 포트폴리오 마감

### 작업

- 홈과 설정 화면 통합
- 날짜별 리포트 기록
- 오류·마지막 갱신 시각 표시
- 샘플 데이터 데모
- README, 구조도, 스크린샷
- 테스트와 정적 검사

### 완료 조건

- PRD의 성공 기준 전체를 체크한다.
- 신규 사용자가 README만 보고 샘플 모드를 실행할 수 있다.
- 실제 API 키 없이 포트폴리오 화면을 재현할 수 있다.
- GitHub에 올려도 되는 파일만 추적된다.
