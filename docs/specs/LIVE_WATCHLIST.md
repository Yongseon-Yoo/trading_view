# 컴포넌트 스펙: 장중 관심종목 실시간 체결

> 상태: IMPLEMENTED - 실제 WebSocket 전용, 테스트 대체 스트림 검증

## 목적

등록된 관심 종목의 실제 체결 흐름을 장중에 한 화면에서 확인하고, 포트폴리오에서 WebSocket 기반 실시간 데이터 처리 역량을 보여준다. 매매 신호나 주문 기능은 제공하지 않는다.

## 입력

- 관심 종목 코드 목록
- 사용자의 `실시간 시작` 또는 `실시간 중지` 명령
- 키움 운영 또는 모의투자 인증정보
- 데이터 모드: `kiwoom` (인증정보가 없으면 시작 불가)

## 출력

```text
LiveWatchlistState
- connection_status
- connected_at
- last_event_at
- stock_states{}
- errors[]
```

각 체결 이벤트:

```text
TradeTick
- stock_code
- price
- change_rate
- trade_volume
- cumulative_volume
- executed_at
- received_at
```

## 처리 규칙

1. 사용자가 시작을 누르면 등록 종목 코드를 키움 `0B 주식체결` 타입으로 한 번에 등록한다.
2. 공급자 응답을 공통 TradeTick 모델로 변환한다.
3. 종목 카드는 가장 최근 이벤트 값으로 갱신한다.
4. 종목별 버퍼에는 최근 5분 이벤트만 유지하며 300건을 초과하면 오래된 이벤트부터 제거한다.
5. 버퍼의 체결가로 연결 이후 실시간 선 그래프를 갱신한다.
6. 사용자가 중지를 누르거나 화면 세션이 종료되면 구독을 해제하고 연결을 닫는다.
7. 버퍼는 메모리에만 유지하며 SQLite와 날짜별 리포트에는 저장하지 않는다.
8. 인증정보가 없거나 체결이 없을 때는 가상 이벤트를 만들지 않고 설정 필요 또는 수신 대기 상태를 표시한다.

## 성공 기준

- 하나의 연결에서 복수 관심 종목을 구독한다.
- 연결 중·연결됨·재연결 중·종료·오류 상태를 화면에서 구분할 수 있다.
- 종목별 현재가, 등락률, 체결량, 누적거래량과 마지막 체결 시각이 갱신된다.
- 최근 체결가 선 그래프가 새 이벤트에 따라 갱신된다.
- 중지 후 추가 이벤트가 화면에 반영되지 않는다.
- 실시간 데이터를 영구 저장하지 않는다.
- 실제 키 없이 시작할 수 없으며 설정 안내가 표시된다.

## 엣지 케이스

| 상황 | 처리 |
|---|---|
| 관심 종목 없음 | 시작 버튼을 비활성화하고 종목 등록 안내 |
| 장 마감 또는 체결 없음 | 연결 상태와 `수신 대기 중` 표시 |
| 인증 실패 | 오류 표시, 가상 스트림으로 전환하지 않음 |
| 연결 끊김 | 제한된 횟수로 재연결하고 상태 표시 |
| 일부 종목 이벤트 없음 | 다른 종목 스트림은 유지하고 해당 종목만 대기 표시 |
| 이벤트 폭주 | 최근 5분·최대 300건 버퍼 제한 적용 |
| 중복 이벤트 | 종목코드·체결시각·가격·체결량·누적거래량 조합으로 중복 제거 |

## 범위 밖

- 실시간 호가잔량
- 주문·체결 계좌 이벤트와 잔고
- VI 발동·해제 이벤트
- 조건검색 실시간 이벤트
- 규칙 기반 알림
- 자동매매와 주문 실행
- 틱 데이터 영구 저장 및 백테스트

## 테스트

- 복수 종목 등록 패킷 생성 테스트
- 키움 이벤트 파싱 및 TradeTick 변환 테스트
- 최근 5분·최대 300건 버퍼 테스트
- 중복 이벤트 제거 테스트
- 시작·중지 및 연결 상태 전이 테스트
- 인증정보 누락 시 시작 차단 테스트
- 연결 실패와 제한 재연결 테스트
